## Entscheidungen

- **Starter-Entscheidungen heißen E-NN, nicht D-NN.** STRANDS nennt D-01; D kennzeichnet aber die Designregeln in `CLAUDE.md` Teil A (G1). E-NN folgt außerdem `app-starter`. Steht als Hinweis oben in `docs/DECISIONS.md`.
- **Hooks in Python 3.9**, ohne Pakete (BAUPLAN §2.15). `announce-directives` ist zusätzlich zu STRANDS portiert, weil `docs/vorlagen/VORGABEN.md` auf ihn verweist; er liest `origin/<default>` nur aus dem lokalen Ref und ruft das Netz nicht ab.
- **Test des JavaScript-Workflows ohne Node:** der Test entfernt den `meta`-Block und führt den Körper mit Stellvertretern für `agent`, `parallel`, `phase`, `log` in JavaScriptCore aus (`osascript -l JavaScript`; Promises laufen nach dem Skript auf oberster Ebene ab). Auf Nicht-Macs wird die Klasse übersprungen.
- **Rechte:** Deny-Muster sperren die einstellende Form, nicht das Wort (`grep hooksPath` bleibt erlaubt; Test). `sudo` nur am Anfang oder nach `&&`, `;`, `|` gesperrt, damit `grep sudo` läuft. `make run`, `open`, `bin/starter init/remove/strip-examples/sync`, `tccutil`, DMG, Signatur und Notarisierung fragen nach; `tccutil reset All` ohne Bundle-ID ist gesperrt.
- **CI (Stand nach Review siehe unten):** Python-Prüfungen auf `ubuntu-latest` (mit `apt-get install zsh` für das Makefile), Build, Tests, Renders, DMG und Proben auf `macos-26` (laut `actions/runner-images` arm64, macOS 26.6, Xcode 26.0.1 bis 26.6, Standard 26.6). Xcode über `DEVELOPER_DIR=/Applications/Xcode_26.6.app/Contents/Developer` fest, ohne `sudo xcode-select`. Aktionen `actions/checkout@v7`, `actions/upload-artifact@v7` (neueste Releases per `gh api`). Build-Matrix: starter.json, `window`, `menubar`, `window,menubar`, `menubar,island`, `menubar,background`, `window,hotkeys`, `window,ai`, `window,ai,mlx`, alle; jeweils `codesign --verify --strict` und `--selftest` mit `STARTER_HEADLESS=1`. DMG nur bei Tags `v*`. Template-Probe: frische Kopie, `bin/starter init --non-interactive`, Commit ohne Identität muss scheitern, `make check`. Modul-Entfernung je Modul in einer frischen Kopie, „alle“ prüft zusätzlich, dass `menubar` als letzte Form nicht entfernbar ist.
- **Gatekeeper:** Doku sagt „Trotzdem öffnen“ in den Systemeinstellungen; den Weg über Rechtsklick und „Öffnen“ gibt es auf aktuellem macOS nicht mehr (vb-packaging.md §7).
- **SF Symbols im App-Symbol:** Apple untersagt SF Symbols in App-Symbolen und Logos. Doku (`THIRD_PARTY_NOTICES.md`, `docs/VERTEILUNG.md` §8, `docs/DESIGN.md` §10, `CHANGELOG.md`, README „fertig“) behandelt das Symbol aus `make icon` deshalb als Entwicklungsstand; vor der ersten Weitergabe ein eigenes Motiv.
- **Agenten in der Cloud:** Linux-Container können nicht bauen; `docs/UEBERGABE.md` §4 empfiehlt Claude Code auf dem Mac für App-Arbeit und die Cloud für Doku und Regeln, die CI auf `macos-26` übernimmt Build und Renders.
- **Regelkennungen:** Doku und Agenten nennen Regeln nach Gruppe (Schreib-, Design-, Technikregeln in `CLAUDE.md` Teil A), keine Nummern, weil G1 die Nummern parallel festlegt.

## Bekannte Lücken

- Die CI lief nie auf GitHub (nichts gepusht). Neu ungetestet auf GitHub: Matrix aus `fromJSON(needs.plan.outputs.…)`, die Bedingung mit `github.event.repository.default_branch` und `/usr/bin/python3` auf dem Runner (laut Image Apples 3.9 aus Xcode). YAML mit Ruby geparst, Inhalt per Test geprüft; Runner-Labels und Xcode-Pfade aus `actions/runner-images` (Stand heute), nicht auf einem Runner bestätigt. Ob `make shots` auf dem Runner ohne angemeldete Sitzung rendert, ist offen (toolchain-probe Risiko 2).
- Die Prüfskripte von G1 und K fehlen in diesem Worktree; `make check` überspringt sie. Gegen eine Kopie dieses Stands mit den unfertigen Skripten aus dem G1-Worktree: `check_texts.py --streng` meldet 30 Befunde, keinen davon in G2-Dateien (alle in `App/Sources` und `App/Tests` von S0/S0b).
- Skills und `docs/MODULE.md` beschreiben die Modul-APIs nach STRANDS; die Module sind noch Stubs. Ebenso sind die README-Bilder Platzhalter.
- Der Abgleich der Rechte im Test ist ein Nachbau der Regeln von Claude Code (Stern, abschließendes ` *`), nicht der echte Abgleich.
- `session-start.py` führt bei jedem Sessionstart `scripts/doctor.sh` aus (einige Sekunden wegen der Typprüfung); auf Nicht-Macs wird es übersprungen. Ein `SDKROOT`, das nicht xcruns Standard ist, gibt der Hook weiter (gleiche Regel wie `bin/starter`).
- `guard-git.py` liest Git-Argumente nach, ist aber keine Sandbox: Git über ein Skript, einen Alias oder eine Variable wie `$G commit -n` erkennt er nicht. Die CI prüft Autor und Format aller Commits erneut.
- `announce-directives.py` liest `origin` nur aus dem lokalen Ref (kein `git fetch`); neue Vorgaben auf `origin` erreichen einen Branch erst nach dem nächsten Fetch.
- Die Doku kennt nur die Kit-Szenen, die es heute gibt; wenn D und E ihre Szenen anders benennen, muss `docs/screenshots/list.txt` folgen.
