## Bekannte Schwächen

- `guard-git.py` liest Shell-Text; ein Skript oder Alias kann git und make anders aufrufen. Die CI wiederholt die Prüfungen.
- Ein Merge über GitHub auf `main` lässt `make check` aus und verlässt sich auf den grünen Pull Request; das stimmt nur mit Branchschutz `strict=true` (UEBERGABE §5). Typecheck und Renders laufen trotzdem.
- `onboarding.project` zeigt die Schritte, deren `isIncluded` auf dem rendernden Mac zutrifft (etwa ohne „Mit dem Mac starten“, solange die App nicht installiert ist).
- Die Zeiten in der Minuten-Tabelle sind geschätzt (Dreifaches der lokalen Zeiten), nicht auf GitHub gemessen; die CI-Datei ist lokal nur über Tests und `ci_plan.py` geprüft, nicht auf GitHub gelaufen.
- `requirements.lock` ist nur offline mit pips Parser geprüft, die Installation mit `--require-hashes` nicht ausgeführt (kein Download ohne Auftrag).
